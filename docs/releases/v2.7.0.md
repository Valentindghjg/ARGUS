# ARGUS v2.7.0 — Clear states, local automation and checked releases

## In short / Kurz gesagt

- The first release since 1.16.0 brings everything from 2.0 to 2.7. There is one
  free edition built on the Python standard library, and ARGUS is now the name
  everywhere. The release adds:
  - evidence, decisions and security steps kept separately, with undo
  - explained detection and a "What's new" view
  - visible jobs with one global pause and target-bound approvals
  - a watched export folder, a Bitwarden preview and journal
  - profiles, reports, templates and backups
  - a WCAG 2.2 AA audit, and release files with signed build provenance
- Die erste Veröffentlichung seit 1.16.0 enthält alles aus 2.0 bis 2.7. Es gibt
  eine kostenlose Ausgabe auf Basis der Python-Standardbibliothek, und ARGUS
  heißt jetzt überall so. Neu sind:
  - getrennte Zustände für Hinweise, Entscheidungen und Sicherheitsschritte, mit
    Rückgängig
  - erklärte Erkennung und eine Ansicht „Neu seit…“
  - sichtbare Jobs mit einer Pause für alles und zielgebundenen Freigaben
  - ein überwachter Export-Ordner, Bitwarden-Vorschau und -Journal
  - Profile, Berichte, Vorlagen und Sicherungen
  - eine Prüfung nach WCAG 2.2 AA und Release-Dateien mit signierter
    Herkunftsbestätigung

The full list is in the
[change log](https://github.com/Valentindghjg/ARGUS/blob/v2.7.0/docs/CHANGELOG.md)
and in the [Änderungen](https://github.com/Valentindghjg/ARGUS/blob/v2.7.0/docs/AENDERUNGEN.md).

## Upgrading from 1.x / Umstieg von 1.x

- Install the wheel `argus_account_security-2.7.0-py3-none-any.whl`. The
  command is `argus`. `account-finder` and `python -m account_finder` still
  work but print a deprecation notice. Pro licensing is gone and every feature
  is free. ARGUS no longer needs `cryptography`.
- The default profile moves once from `~/.local/share/account-finder` to
  `~/.local/share/argus`. A profile given with `--data-dir` is never moved.
- The first start saves a backup of the old profile, then migrates the
  database. Once migrated, ARGUS 1.x can no longer open the profile.
- Scheduled IMAP scans from 1.x need one new `enable`. Each approval is now
  bound to host, port, user, sign-in method and folders.
- Das Wheel heißt `argus_account_security-2.7.0-py3-none-any.whl`, der Befehl
  `argus`. Das Standardprofil zieht einmal von `account-finder` nach `argus`
  um. Vor der Migration legt ARGUS eine Sicherung an. Geplante IMAP-Scans
  brauchen einmal ein neues `enable`.

## New connections and permissions

No module gained a new way to reach the network or start a program. The browser
companion asks for nothing new. `python scripts/release_check.py` lists the
declared modules and fails when a module reaches out without a declaration.

| Module | What it may do | Changed in this release |
|---|---|---|
| `imap_client.py` | Reads the mailbox over TLS IMAP, only with `scan-imap --allow-imap` or an approved scheduled scan. | Yes. A scheduled scan's approval is bound to its target, shown in the dashboard and revocable there. The global pause stops it between two messages. The scheduler checks once a minute while the dashboard runs, so a schedule enabled in a terminal starts without a restart. |
| `discovery.py` | Asks the DNS resolver for MX records, only with `--allow-dns`. | no |
| `bitwarden.py` | Runs the official Bitwarden CLI that you unlocked, only after your confirmation. | Yes. It uses the same commands as before (`status`, `list items`, `create item`). Item data now goes to `bw` through standard input instead of the command line. On Windows only `bw.exe` from a `PATH` folder runs. Each transfer is journaled against duplicates. |
| `server.py` | Serves the dashboard on 127.0.0.1 only and opens it in your browser when you pass `--open`. | no; new endpoints are local |
| Browser companion | Permission `activeTab` only. | no |

## Data and migrations / Daten und Migrationen

- Database schema: from the 1.x schema to 11. ARGUS saves a backup before it
  migrates a profile and keeps the newest five automatic ones. It refuses a
  profile from a newer ARGUS.
- New local files and folders:
  - `backups/` in the profile holds automatic and manual backups as unencrypted
    ZIP files.
  - `my-providers.json` in the profile holds your own catalog additions.
  - Named profiles (`--profile NAME`) live under
    `~/.local/share/argus-profiles/NAME`.
- Reports and Bitwarden files are written only where you save them. The folder
  watch reads one local folder that you approved and never changes it.

## Verify the files / Dateien prüfen

Compare the files with `SHA256SUMS` from this release, for example
`sha256sum --check SHA256SUMS` on Linux or
`Get-FileHash <file> -Algorithm SHA256` in PowerShell. The "Release files"
workflow run for this tag lists the same checksums in its summary. The wheel is
built reproducibly, so a local build of the tag gives the same wheel checksum.

The same run attested where the files come from. With the GitHub CLI:
`gh attestation verify <file> --repo Valentindghjg/ARGUS`. It succeeds only for
a file built by the "Release files" workflow of this repository.

## Checked with / Geprüft mit

The checks used synthetic data only:

- 406 Python tests on Linux, Windows and macOS
- 38 browser check groups and the multi-account check
- a WCAG 2.2 AA audit with axe-core over 88 view, dialog, language and width
  states, with 0 violations

No real mailbox, password, provider account or Bitwarden vault was used.

## Limits that stay / Grenzen, die bleiben

Clues in emails are no proof of an account, and an unknown account is not an
absent one. ARGUS changes nothing at providers and never stores passwords. The
accessibility audit is automated; a review with screen readers is still to
come.
